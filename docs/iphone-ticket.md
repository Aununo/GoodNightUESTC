# 从 iPhone 导入本人打卡票据

Shadowrocket 只需为 `jzsz.uestc.edu.cn` 开启 HTTPS 解密。本人从“成电智慧学工”
进入“晚安成电”后，在带 `MITM` 标记的 `/daily-checkin-h5/index.html` 请求中
找到 `checkinTicket`，复制完整入口 URL。不要把链接或票据发到聊天或写进命令。
学校域名可以使用 `DIRECT`；不需要为了取得票据额外提交打卡。

## 一次设置快捷指令

在 iPhone“快捷指令”中创建一个指令，按顺序加入：

1. **获取剪贴板**。
2. **通过 SSH 运行脚本**，输入选择上一步的“剪贴板”。主机、端口、用户名
   使用本人服务器的实际 SSH 信息。认证选择 SSH 密钥，在手机本机生成密钥，
   由服务器管理员安装其公钥。私钥不应离开手机或发送到聊天。
3. **从输入中获取文本**，输入选择 SSH 操作的输出（其类型显示为 File 是正常的）。
4. **显示结果**，显示上一步的文本。

SSH 脚本填写固定命令，把路径和账号替换为实际值（以默认账号为例）：

```sh
exec /path/to/node /path/to/goodnight/bin/goodnight.mjs authorize --data-dir /path/to/data-root --account default --ticket-stdin
```

运行时，URL 通过 SSH 的标准输入传入，不插进脚本文本、不成为命令行参数，
也不需要在服务器上另存临时明文文件。不要在脚本中使用剪贴板变量拼接 `echo`、
`printf` 或命令。

若管理员把这把手机公钥限制到 `scripts/authorize-from-iphone.mjs default`，
快捷指令的脚本栏只需填写 `goodnight-authorize`，无需填写上面的完整命令。
另建一个脚本栏为 `goodnight-status` 的快捷指令可查看该账号状态。
受限公钥需要同时使用 OpenSSH 的 `restrict` 选项，禁止交互终端、端口转发和其他命令。
不要通过开放服务器密码登录来替代这一步。

每个账号应使用自己的快捷指令或明确选择对应账号，不能把一个账号的票据分发到
其他账号目录。服务器只会核验本地业务登录身份；票据本身是否属于该账号由学校
最终判断，所以导入前必须由本人确认账号。

## 结果与后续更新

- `authorization_available`：票据已保存在对应账号的私有文件中，尚不代表学校已接受。
- `serverVerified=false`：尚未以真实打卡验证；导入操作不会提交打卡。
- `already_running`：该账号正被后台任务占用，稍后重跑快捷指令即可。
- 输入错误、超时或超出 32 KiB：不启动业务验证，不保存该输入，不在错误中回显票据。

手机导入入口会把成功和失败说明都写到标准输出，供快捷指令显示；同时在该账号私有
目录保存 `last-iphone-request.json` 和不含票据的事件日志。快捷指令结束的勾号不是
导入成功证明，应查看输出中的 `result`。

票据过期时，重新从微信小程序进入、复制新的入口 URL，再运行同一快捷指令。
这不是自动续签；学校控制有效期。服务器后续定时提交仍保留原有时间窗口、地点校验
和防重复提交规则，学校明确拒绝票据时会停用它。

第一次导入后应查看程序的状态，并以学校保存的 `CHECKED_IN` 确认实际打卡成功。
票据失效后的恢复及私有文件导入方法见 [Linux 文档](linux-server.md#打卡授权票据)。
